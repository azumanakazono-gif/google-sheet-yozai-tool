# 週次予材リスト同期スクリプト (Google Apps Script)

Google Driveフォルダ内のExcel/スプレッドシートを読み取り、「31期予材リスト」スプレッドシートの
「報告記録」シート末尾に自動追記するGASスクリプトです。追記と連動して、見込確度が変化した
案件だけを「週次ステータス変更履歴」シートにも自動記録します。

- 取得元フォルダ: `1WrjMUtIpe2JEwChiJygRs1TeqWGgPuyc`
- 追記先スプレッドシート: `1zTz2lLUD6M4SPBCcEO3OBxNMmv1U7RsUYRJhkKkgOOQ`（シート「報告記録」。`Config.gs`の`TARGET_SHEET_NAME`で変更可能）

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `appsscript.json` | マニフェスト（タイムゾーン等のみ。Advanced Serviceや特別な`oauthScopes`設定は不要） |
| `Config.gs` | フォルダID・シート名などの設定値 (`CONFIG`) |
| `Main.gs` | メイン処理 (`syncWeeklyReports`)、週次トリガー(`installWeeklyTrigger`)・見込確度手動編集トリガー(`installConfidenceChangeTrigger`)をスクリプトから設定するためのヘルパー、処理済みログのリセット関数(`resetProcessedLog`) |
| `ReportSync.gs` | 「週次報告記録」シートへの追記処理 (`appendFileToTargetSheet_`) |
| `StatusHistory.gs` | 「週次ステータス変更履歴」シートの自動更新処理。バッチ取り込み時(`updateWeeklyStatusHistory_`)・「今月」等の予材シートでの手動編集時(`onConfidenceCellEdited`)の両方の履歴作成・数式コピー・案件名リンク生成処理を含む |
| `Utils.gs` | 取り込み元ファイルのパース(`parseWeeklyReportFile_`等)、および Drive・シート操作まわりの共通ユーティリティ関数 |
| `コード.gs` | 上記5ファイルを1本にまとめた単一ファイル版。GASの標準ファイル名「コード.gs」にそのまま丸ごと貼り付けて使う想定 |

`Config.gs`/`Main.gs`/`ReportSync.gs`/`StatusHistory.gs`/`Utils.gs`の5分割と`コード.gs`の単一ファイルは中身が重複しているだけで、同時に使う必要はない。GASプロジェクトにファイルを分けて置くなら前者5つを、1ファイルで完結させたいなら`コード.gs`のみを使う。**同一プロジェクト内で両方を貼り付けると`CONFIG`などが二重定義されエラーになるので注意。**

## 処理内容

1. `SOURCE_FOLDER_ID` フォルダ直下のファイルを走査する。対象はGoogleスプレッドシートおよびExcel(.xlsx/.xls)・CSV/TSV(.csv/.tsv)。ANDPAD出力ファイルはmimeTypeが正しく設定されないことがあるため、mimeTypeで判定できない場合はファイル名の拡張子でもフォールバック判定する。
2. Excel/CSVファイルは **手動変換不要・外部API呼び出し不要** で読み取る（`parseWeeklyReportFile_`）。ANDPAD等の出力は「拡張子は.xlsxだが中身が標準ZIPではない」ことがあるため、ファイル先頭のマジックバイトや中身のテキストで実体を判別し、以下の順にフォールバックする。途中の形式でのパースに失敗しても即エラーにはせず、ログを残して次の形式を試す。
   1. **本物の.xlsx(ZIP構造)**: `.xlsx`の実体はZIPアーカイブなので、GAS標準の`Utilities.unzip`でXMLを取り出し、同じくGAS標準の`XmlService`でパースして値を抽出する（`parseXlsxZipDirectly_`）。
   2. **旧形式バイナリ.xls(OLE構造)**: パースできないため、「.xlsxまたはCSVで保存し直してください」という明確なエラーメッセージを出して`エラー`フォルダへ移動する。
   3. **HTMLテーブルを.xlsx/.xlsとして出力しているケース**: 内容が実はHTMLと判定できた場合、`<table>`をHTMLとして解析して値を抽出する（`parseHtmlTableBlob_`。複数`<table>`がある場合は行数が最も多いものを本体とみなす。Shift_JIS系のcharset宣言があれば自動でその文字コードとして読み直す。`<table>`/`<tr>`が1件も取れない場合はエラーとして次のCSVフォールバックへ進む）。
   4. **CSV/TSVをテキストとして出力しているケース**: 先頭行のカンマ/タブ出現数から区切り文字を自動判定し、ダブルクォート囲み・囲み内の改行/カンマ・`""`エスケープに対応した簡易パーサで解析する（`parseCsvBlob_`）。

   Advanced Drive Service・UrlFetchApp・Drive REST APIなど、Driveの外部変換処理は一切使わない。**なお「DriveAppで一時的にGoogleスプレッドシート形式に変換する」処理自体はGASに存在しない**（フォーマット変換ができるのはDrive APIのみで、それは上記の理由により使わない方針としている）。そのため上記4パターンのいずれにも当てはまらない、完全に破損した/未知の形式のファイルは読み取れず、検出されたContentTypeと先頭バイトのプレビューを含む明確なエラーメッセージとともに`エラー`フォルダへ移動される。
3. 列は **ヘッダー名でマッチング** して「週次報告記録」シートに書き込む。ANDPAD側で列の並び順が変わったり、新しい列が追加されたりしても、既存の列名と一致するものは対応する列にそのまま入り、未知の列名が来た場合はシートのヘッダーに自動で追加される（「フォーマットの揺れ」への対応）。取込日時・元ファイル名は常に先頭2列に入る。
4. 追記が終わったファイルは `処理済み` サブフォルダへ移動し、次回以降のスキャン対象から除外することで二重処理を防止する。同名ファイルが既に `処理済み` にある場合（ANDPADが毎回同じファイル名で出力するケースを想定）はタイムスタンプを付けてリネームしてから移動するため、上書き・混同は起きない。
5. 追記が完了した時点でファイルIDをスクリプトプロパティに記録する。仮にその後の「処理済みフォルダへの移動」が失敗しても、次回実行時は記録済みIDのファイルを再追記せずスキップし、移動だけを再試行する（二重処理防止の保険）。
6. 読み取りや書き込みに失敗したファイルは `エラー` サブフォルダへ移動し、`NOTIFY_EMAIL` を設定していればエラー内容をメール通知する。

`処理済み`・`エラー` フォルダは `SOURCE_FOLDER_ID` の直下に初回実行時に自動作成されます。

## 週次ステータス変更履歴の自動記録

「週次報告記録」への追記が完了する**たびに**(`appendFileToTargetSheet_`の中で)、直後に
`updateWeeklyStatusHistory_`が連動して呼ばれ、「週次ステータス変更履歴」シートを更新します。

1. 今回追記した行(直近の取り込み分)を、追記前に既に「週次報告記録」にあった行と
   **案件名**(`CONFIG.STATUS_HISTORY_KEY_COLUMN_CANDIDATES`)で突き合わせる。
2. **見込確度**(`CONFIG.STATUS_HISTORY_CONFIDENCE_COLUMN_CANDIDATES`)について、
   **変更前見込確度が空欄でなく、かつ変更前後で値が異なる**案件だけを転記対象として抽出する
   (変化していない案件・変更前が空欄の新規登録案件・今回が初登場の案件はいずれも対象外)。
3. 対象案件について、記録日時・担当・案件名・カテゴリ・次回アクション予定日時・
   ネクストアクション・変更前後の見込確度・変更経緯・最新見積格納日・契約見込月・
   税込想定売上・貢献利益率・備考（状況）を「週次ステータス変更履歴」シートの末尾に追記する
   (`CONFIG.STATUS_HISTORY_COLUMNS`)。列は名前でマッチングするため、既存シートの
   列順が変わっていても正しい列に入る。
4. **昇降フラグ列(既定では「昇降フラグ」列名、G列を想定)には値を書き込まない。**
   この列は「変更前見込確度」「変更後見込確度」を比較して↑/↓を算出するスプレッドシート側の
   数式が元々セットされている前提のため、GAS側はコピー元となる既存行(数式が入っているセル)から
   `Range.copyTo(..., SpreadsheetApp.CopyPasteType.PASTE_FORMULA, false)` で数式だけを
   新規追記行にコピーする(`applyRankFlagFormula_`)。コピー元は直前行固定ではなく、
   直前行から見出し行の次の行まで遡って実際に数式が入っている最も近い行を探す
   (`findNearestFormulaRow_`)ため、直前行だけがたまたま数式なし・空欄等の場合でも
   既存の数式を確実に引き継げる。数式が入った行が1件も見つからない場合のみスキップされ、
   ログにその旨が出力される(その場合はいずれか1行に手動で数式を設定すれば、以降の実行から
   自動でコピーされるようになる)。
5. **案件名セル(C列)には、既存シートの見た目に合わせたリンク付きリッチテキストを設定する。**
   フォントカラーは`CONFIG.STATUS_HISTORY_LINK_COLOR`(既定 `#1155cc`、Google Sheetsの
   リンク標準色)、下線ありのスタイルを`SpreadsheetApp.newRichTextValue()`で組み立て、
   `Range.setRichTextValues()`でまとめて反映する(`applyProjectNameLinks_` /
   `buildProjectNameRichText_`)。リンク先は「週次報告記録」の該当行への
   スプレッドシート内部リンク(`#gid=<sheetId>&range=A<行番号>`)とし、案件名をクリックすると
   その案件の最新の取り込み行にジャンプできるようにしている。
   **このリンク先URLは実物のシートを直接確認できない状態での実装上の判断であり、
   もし既存の案件名リンクが外部システム(ANDPAD等)のURLを指している場合は、
   `updateWeeklyStatusHistory_`内の`reportRowLink`の組み立て方を、その実際のURLを
   参照する形に差し替えること。**
6. 履歴記録自体が失敗しても「週次報告記録」への追記は成功として扱う(`appendFileToTargetSheet_`が
   `try/catch`で握りつぶし、ログにのみ記録する)。

**実際のANDPAD出力・スプレッドシートの列名に合わせて`Config.gs`(または`コード.gs`のCONFIG)の
以下の設定値を確認・調整すること**(実物のシートを直接確認できない状態で実装しているため、
既定値はあくまで一般的な想定に基づく):

- `STATUS_HISTORY_SHEET_NAME`: 履歴シート名(既定 `週次ステータス変更履歴`)
- `STATUS_HISTORY_HEADER_ROW`: 列見出しが入っている行番号(既定 `2`。1行目はタイトル行という前提)。実際のシート構成が異なる場合は調整すること
- `STATUS_HISTORY_COLUMNS`: 履歴シートの列構成(既定 記録日時・担当・案件名・カテゴリ・
  次回アクション予定日時・ネクストアクション・昇降フラグ・変更前見込確度・変更後見込確度・
  変更経緯・最新見積格納日・契約見込月・税込想定売上・貢献利益率・備考（状況）(O列))
- `STATUS_HISTORY_RANK_FLAG_COLUMN`: 数式で↑/↓を算出する昇降フラグ列の名前
- `STATUS_HISTORY_LINK_COLOR`: 案件名リンクのフォントカラー(既定 `#1155cc`)
- `STATUS_HISTORY_KEY_COLUMN_CANDIDATES`: 「週次報告記録」側で案件を一意に識別する列名候補
- `STATUS_HISTORY_CONFIDENCE_COLUMN_CANDIDATES`: 転記条件となる「見込確度」列の名前候補
- `STATUS_HISTORY_FIELD_SOURCE_COLUMNS`: 履歴シートの各列に「週次報告記録」側のどの列名を
  転記するかの対応表

案件識別列または見込確度列が「週次報告記録」に見つからない場合は、履歴記録全体をスキップし
ログにその旨を出力する(「週次報告記録」への追記自体は通常どおり成功する)。

## 「今月」等の予材シートでの手動編集の記録

`syncWeeklyReports`によるバッチ取り込みとは別に、「今月」等の**予材シート**(手作業でステータス管理
する現場向けシート)で見込確度列が**手動編集**された場合も、`onConfidenceCellEdited`が変更理由を
入力させた上で「週次ステータス変更履歴」に記録する。

1. 対象シート(`CONFIG.CONFIDENCE_EDIT_SHEET_NAMES`、既定は`今月`のみ)の、見込確度列
   (`CONFIG.CONFIDENCE_EDIT_COLUMN_LETTERS['見込確度']`=既定でO列)への**単一セル編集**を検知する。
   複数セルへの一括貼り付けは、Apps Scriptの仕様上編集前の値(`e.oldValue`)を個別に取得
   できないため対象外(何も起きない)。
   - 「今月」シートは列見出しが「週次報告記録」側と一致しない(または見出し行の構成が異なる)
     ため、ヘッダー名でのマッチングは行わず、`CONFIG.CONFIDENCE_EDIT_COLUMN_LETTERS`に
     設定した**固定の列位置**(案件名/担当/カテゴリ/次回アクション予定日時/ネクストアクション/
     見込確度/最新見積格納日/契約見込月/税込想定売上/貢献利益率/備考（状況）)から直接値を抽出する
     (`readConfidenceEditField_`)。実際の「今月」シートの列位置が変わった場合は、この設定を
     更新する必要がある。
2. `SpreadsheetApp.getUi().prompt(...)`で「変更理由」の入力ダイアログを表示する。
   キャンセル/未入力の場合も、変更自体は理由なしで記録する(セルの値は編集内容のまま)。
3. 記録日時・案件名(`CONFIG.CONFIDENCE_EDIT_COLUMN_LETTERS['案件名']`列)・変更前後の見込確度・
   変更経緯などを、バッチ取り込み時と同じ`STATUS_HISTORY_COLUMNS`の列構成で
   「週次ステータス変更履歴」の末尾に1行追記する。
   - 記録日時(A列)は`CONFIG.STATUS_HISTORY_TIMESTAMP_FORMAT`(既定`yyyy/MM/dd HH:mm:ss`)の
     日時文字列で書き込む(日付だけでなく時刻まで記録する)。
   - 変更経緯(J列)には、入力ダイアログで入力された理由文字列をそのまま書き込む
     (「見込確度変更: 〜」等の自動生成の定型文は付与しない)。キャンセル/未入力の場合、
     およびバッチ取り込み時(入力ダイアログを経由しないため)は空文字になる。
   - 案件名セル(C列)のリンクは、「今月」シート側の案件名セル(`CONFIG.CONFIDENCE_EDIT_COLUMN_LETTERS['案件名']`列)に
     既にリッチテキストのリンクが設定されていれば、そのリンク先URLをそのまま引き継ぐ
     (`getCellLinkUrl_`)。「今月」シート側にリンクが無い場合のみ、従来通り「今月」シートの
     編集された行への内部リンクにフォールバックする。リンクの色・下線等の見た目自体は
     バッチ取り込み時と同様に`CONFIG.STATUS_HISTORY_LINK_COLOR`のスタイルで統一される。
   - 昇降フラグ列(G列)はスプレッドシート側の既存の数式をそのまま踏襲する(次項参照)。
4. 記録に失敗した場合は例外を投げず、ログとアラート表示に留める(セルの編集自体は既に
   確定しているため、記録失敗を理由に編集を巻き戻すことはしない)。

**この機能を使うには、`installConfidenceChangeTrigger()`を一度だけ手動実行してインストーラブル
トリガー(編集時)を作成する必要がある。**
`onEdit`という名前のまま**単純トリガー**として定義しても、ダイアログ(`Ui.prompt`/`Browser.inputBox`)
は表示できない(Apps Scriptの仕様上の制限)。GASエディタの「トリガー」画面から手動設定する場合も、
必ずイベントの種類を「編集時」にしたインストーラブルトリガーとして追加すること。

案件を追加した本人以外が編集した場合など、ダイアログ表示に失敗するケースでも、変更自体は
理由欄が空欄の状態で記録される(記録が完全に失われることはない)。

## セットアップ手順

**Advanced Serviceの追加もマニフェストの特別な設定も不要です。** DriveApp・SpreadsheetApp・Utilities・XmlServiceはすべてGASの標準サービスで、有効化操作は要りません。`appsscript.json`はタイムゾーン設定程度のシンプルな内容です。

### 単一ファイル版（`コード.gs`）を使う場合（迷ったらこちら）

1. [script.google.com](https://script.google.com) で新規プロジェクトを作成する（「31期予材リスト」に紐づくコンテナバインド型でも、スタンドアロン型でもどちらでも可）。
2. デフォルトで存在する「コード.gs」を開き、**中身を全選択して一度すべて削除**してから、この`コード.gs`の内容を丸ごと貼り付ける（既存コードの一部が残っていると構文エラーの原因になるため、必ず全削除してから貼り付けること）。
3. エディタ上部の関数選択で `syncWeeklyReports` を選び、一度手動実行して権限承認（Drive・スプレッドシートへのアクセス許可）を行う。
4. 実行ログ (表示 → 実行数、またはログ) で正常終了・追記結果を確認する。

### 分割ファイル版（`Config.gs`/`Main.gs`/`ReportSync.gs`/`StatusHistory.gs`/`Utils.gs`）を使う場合

1. 上記1と同様にプロジェクトを作成する。
2. `Config.gs` / `Main.gs` / `ReportSync.gs` / `StatusHistory.gs` / `Utils.gs` の内容をそれぞれ同名のスクリプトファイルとして貼り付ける（デフォルトの「コード.gs」は削除するか空にしておく）。
3. 上記の3〜4と同様の手順（手動実行 → 権限承認 → ログ確認）を行う。

## 週次トリガーの設定手順

### 方法A: GASエディタから手動設定（推奨）

1. エディタ左メニューの時計アイコン「トリガー」を開く。
2. 右下「トリガーを追加」をクリック。
3. 以下を設定して保存する。
   - 実行する関数を選択: `syncWeeklyReports`
   - 実行するデプロイを選択: `Head`
   - イベントのソースを選択: `時間主導型`
   - 時間ベースのトリガーのタイプを選択: `週タイマー`
   - 曜日を選択: 任意（例: 月曜日）
   - 時刻を選択: 任意（例: 午前6時〜7時）
4. 保存すると一覧に週次トリガーが表示される。

### 方法B: スクリプトから設定

エディタ上部の関数選択で `installWeeklyTrigger` を選び、一度実行する。
毎週月曜6時台に `syncWeeklyReports` を実行するトリガーが作成される（既存の同名トリガーがあれば作り直される）。
曜日・時刻を変えたい場合は `Main.gs` の `onWeekDay(...)` / `atHour(...)` を編集する。

## 見込確度の手動編集トリガーの設定手順

「今月」等の予材シートでの手動編集を検知して変更理由ダイアログを出す機能（前述）を使うには、
以下のいずれかの方法で **インストーラブルトリガー（編集時）** を設定する必要がある。
（単純トリガーの `onEdit` ではダイアログを表示できないため、この設定を省略すると
セルの変更自体はできても履歴は記録されない。）

### 方法A: スクリプトから設定（推奨）

エディタ上部の関数選択で `installConfidenceChangeTrigger` を選び、一度実行する。
実行時にDrive・スプレッドシートに加え、UI操作（ダイアログ表示）の権限承認を求められる場合がある。
既存の `onConfidenceCellEdited` 用トリガーがあれば作り直される。

### 方法B: GASエディタから手動設定

1. エディタ左メニューの時計アイコン「トリガー」を開く。
2. 右下「トリガーを追加」をクリック。
3. 以下を設定して保存する。
   - 実行する関数を選択: `onConfidenceCellEdited`
   - 実行するデプロイを選択: `Head`
   - イベントのソースを選択: `スプレッドシートから`
   - イベントの種類を選択: `編集時`
4. 保存すると一覧にトリガーが表示される。

## 補足・前提条件

- 取り込むのは各ファイルの **1シート目のみ**。複数シートを取り込みたい場合は `appendFileToTargetSheet_` / `parseWeeklyReportFile_` を修正してループさせる。
- 対応形式は **.xlsx(ZIP構造)・HTMLテーブル(拡張子だけ.xlsx/.xlsのケースを含む)・CSV/TSV** の3種類。旧形式のバイナリ.xls(Excel 97-2003, OLE構造)は読み取れず、エラーとして`エラー`フォルダへ移動される。ANDPADから.xls形式で出力される場合は、事前に.xlsxまたはCSVで保存し直すか、ANDPAD側の出力設定を確認すること。
- HTMLテーブルとして読み取る場合、複数の`<table>`がある中から行数最多のものを自動選択するが、レイアウト目的の入れ子テーブル構成によっては意図しないテーブルが選ばれる可能性がある。その場合は`parseHtmlTableBlob_`のテーブル選択ロジックを対象ファイルの実際の構造に合わせて調整すること。
- CSV/TSVとして読み取る場合、区切り文字は1行目のカンマ数とタブ数を比較して自動判定する(タブの方が多ければTSV扱い)。判定を誤る場合は`detectCsvDelimiter_`を対象ファイルの形式に合わせて調整すること。
- **日付・数値の書式は反映されない。** セルの生の値（文字列/数値/真偽値）をそのまま読み取るため、日付書式が設定されたセルはExcel内部のシリアル値（例: `45123`）としてそのまま入る。日付として扱いたい場合は、取り込み後にスプレッドシート側で書式設定するか、`extractCellValue_`にシリアル値→Dateの変換を追加する。
- 列はヘッダー名（1行目）でマッチングするため、ANDPAD側で列順が変わったり列が増えたりしても正しい列に入る。ただし **表記ゆれ（例:「品名」と「品目名」など別名扱い）までは自動判定しない**。表記ゆれを吸収したい場合は `ensureColumnsExist_` / `appendFileToTargetSheet_` にエイリアス変換表を追加する。
- `Config.gs` の `SOURCE_HAS_HEADER` が `false` の場合は「列1」「列2」...という仮のヘッダー名で取り込む（フォーマット変動への耐性は下がる）。
- `Config.gs` の `NOTIFY_EMAIL` にメールアドレスを設定すると、処理失敗時のみ通知メールが届く。
- 処理済みファイルIDの記録（スクリプトプロパティ `PROCESSED_FILE_IDS`）は直近 `PROCESSED_LOG_MAX` 件のみ保持する。件数を増減したい場合は `Config.gs` を編集する。

## トラブルシューティング

- **`TypeError: Drive.Files.create is not a function` / `Bad Request` (Drive.Files.insert)**: いずれも過去のバージョンでAdvanced Drive Service経由のExcel変換を使っていた際に、GASエディタの「サービス」で追加したバージョン(v2/v3)やAPIの呼び出し方の不一致で発生していたエラー。現在のコードはAdvanced Drive Service・Drive REST API・UrlFetchAppを一切使わず、`Utilities.unzip`と`XmlService`だけで.xlsxを直接パースするため、これらのエラーは原理的に発生しない。
- **`Exception: Service Spreadsheets failed while accessing document with id ...`**: 対象ファイルのmimeTypeが`application/vnd.google-apps.spreadsheet`(Googleスプレッドシート)と判定されたにもかかわらず、そのIDをGoogleスプレッドシートとして開けなかった場合に発生する。多くの場合、GAS側のコードが最新版に更新されておらず、貼り付け時にコードの一部が古いまま残っている（後述の構文エラーと同根の問題）。まずコード全体を最新版で完全に置き換えてから再実行すること。
- **`Exception: セル ... に入力したデータは、このセルで設定しているデータの入力規則に違反しています。`**: 「週次報告記録」シートの列(例: 商材区分)にプルダウン等のデータ入力規則(リスト検証)が設定されている場合、元データにそのリストにない値が含まれていると`setValues`が例外を投げ、追記全体が失敗する。これを避けるため、`appendFileToTargetSheet_`は追記範囲へ書き込む直前に`writeValuesIgnoringValidation_`でその範囲の入力規則を一時的にクリアし、書き込み後すぐに元の規則を復元する(Sheetsの入力規則は入力時のみ検証され、既存セルに規則を再設定しても遡って再検証されないため、復元してもエラーにはならず、以降の手入力用プルダウンはそのまま使える)。このガードは`Utils.gs`/`コード.gs`の両方に入っているため、リスト外の値があっても追記自体は弾かれない。
- **「週次ステータス変更履歴」への追記位置が大きくズレる(例: 103行目のはずが655行目に追記される、または既存の4行目以降を上書きしてしまう)**: `Sheet.getLastRow()`はシート全体(どの列でもよい)の最終行を返すため、実際のデータとは無関係な列に離れた場所まで書式やゴミデータが残っていると、実データの最終行より大幅に手前/先の行を誤って返すことがある。また「週次ステータス変更履歴」シートは**1行目=タイトル行・2行目=列見出し行(`CONFIG.STATUS_HISTORY_HEADER_ROW`)・3行目以降=データ行**という構成のため、この行構成を考慮しないと見出し行のすぐ下(4行目)から上書きしてしまう。これを避けるため、`appendStatusHistoryRows_`は`findLastRowWithValueInColumn_`に「データ開始行(見出し行の次の行)」を渡し、そこから記録日時列(通常A列)に絞って実際の最終データ行を探し、その次の行に追記する。
- **「週次ステータス変更履歴」の転記項目が列ごとズレる(例: 案件名がE列に、変更経緯がK列ではなくL列に入る)**: 履歴シートの実際のヘッダー行に空欄の列(削除済み列の跡など)が挟まっていると発生していた。旧`ensureColumnsExist_`はヘッダー行から空欄セルを`.filter()`で詰めてから列名→列番号のマップを作っていたため、空欄列より右側の列名が実際の列位置とズレるだけでなく、空欄がある度に既存のヘッダー行そのものを詰めて上書きする副作用もあった。現在は空欄を詰めずに実際の列位置をそのまま保持するように修正済み(`Utils.gs`/`コード.gs`の`ensureColumnsExist_`を参照)。また、ヘッダー行が1行目ではなく2行目にあるシート構成にも対応するため、`ensureColumnsExist_`は`headerRowNumber`引数(履歴シートでは`CONFIG.STATUS_HISTORY_HEADER_ROW`)で実際のヘッダー行を指定できるようにした。この修正より前の実行で既にヘッダー行が詰められてしまっている場合は、シートの列見出しと実データの対応を目視で確認し、必要なら手動で列を復元すること。
- **「週次ステータス変更履歴」に、確度が変わっていない案件や新規登録の案件まで大量に記録されてしまう**: 転記条件が「変更前後で見込確度の値が異なる」だけだったため、変更前見込確度が空欄(=その週に初めて確度が設定された新規案件)の場合も「変更あり」として拾われてしまっていた。現在は**変更前見込確度が空欄でなく、かつ変更前後で値が異なる場合のみ**を対象にするよう`updateWeeklyStatusHistory_`(バッチ取り込み時)・`onConfidenceCellEdited`(手動編集時)の両方を修正済み。
- **「今月」シートでの手動編集(`onConfidenceCellEdited`)による転記データが完全にズレる(例: 案件名列に案件名ではなく「[今月 164行目]」が入る、担当・次回アクション・最新見積日・売上金額等が一切反映されない)**: 旧`onConfidenceCellEdited`は「今月」シートの1行目をヘッダー行としてスキャンし、そのヘッダー名を「週次報告記録」側と共通の列名候補(`STATUS_HISTORY_KEY_COLUMN_CANDIDATES`等)でマッチングしていたが、「今月」シートの実際の列見出しはこれらの名前と一致しない(または見出し行の構成自体が異なる)ため、ほぼ全ての列でマッチングに失敗し、案件名は`keyCol`が見つからずフォールバック表示("(今月 164行目)")になり、他の項目も空欄のまま記録されていた。現在はヘッダー名でのマッチングを廃止し、`CONFIG.CONFIDENCE_EDIT_COLUMN_LETTERS`に設定した**固定の列位置**(現在の設定: 案件名=H, 担当=G, カテゴリ=P, 次回アクション予定日時=C, ネクストアクション=D, 見込確度=O, 最新見積格納日=J, 契約見込月=R, 税込想定売上=K)から`readConfidenceEditField_`で直接値を抽出するように修正済み。「今月」シートの列位置が変わった場合は、この設定を更新すること。
- **コード末尾に余計な記号や関数の重複が混入し保存できない**: チャットの表示上は問題なくても、コピー範囲や貼り付けタイミングによって末尾に余分な文字が残ることがある。対処手順:
  1. GASエディタで対象ファイルを開き、`Ctrl+A`（Mac: `Cmd+A`）で全選択して`Delete`し、**空になったことを目視で確認**する。
  2. このリポジトリの`コード.gs`をテキストエディタ等で開いて中身を全コピーし、貼り付ける。
  3. 貼り付け後、`Ctrl+End`でファイル末尾へ移動し、`}`の後に何も残っていないか目視確認する。
  4. それでも解消しない場合は、GASプロジェクトを一度削除して新規プロジェクトを作り直すか、Node.js環境があれば[clasp](https://github.com/google/clasp)でこのリポジトリのファイルを直接pushする方法が最も確実（コピー&ペーストの手順自体を経由しないため）。
