# 週次予材リスト同期スクリプト (Google Apps Script)

Google Driveフォルダ内のExcel/スプレッドシートを読み取り、「31期予材リスト」スプレッドシートの
「週次報告記録」シート末尾に自動追記するGASスクリプトです。あわせて、「今月」シートの見込確度
編集を検知して「週次報告記録」「週次ステータス変更履歴」へ自動転記する機能も含みます。

- 取得元フォルダ: `1WrjMUtIpe2JEwChiJygRs1TeqWGgPuyc`
- 追記先スプレッドシート: `1zTz2lLUD6M4SPBCcEO3OBxNMmv1U7RsUYRJhkKkgOOQ`（シート「週次報告記録」「週次ステータス変更履歴」）

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `appsscript.json` | マニフェスト（タイムゾーン等のみ。Advanced Serviceや特別な`oauthScopes`設定は不要） |
| `Config.gs` | フォルダID・シート名・対象期間判定・編集監視などの設定値 |
| `WeeklySync.gs` | 週次自動転記のメイン処理 (`syncWeeklyReports`)、対象期間の自動判定ロジック |
| `EditSync.gs` | 編集時トリガー (`onEdit` / `handleEdit_`)。「今月」シートの見込確度編集を検知して自動転記する |
| `Triggers.gs` | 週次トリガー (`installWeeklyTrigger`) / 編集時インストーラブルトリガー (`installEditTrigger`) をスクリプトから設定するためのヘルパー |
| `コード.gs` | 上記4ファイル + ログリセット用関数 (`resetProcessedLog`) を1本にまとめた単一ファイル版。GASの標準ファイル名「コード.gs」にそのまま丸ごと貼り付けて使う想定 |

`Config.gs`/`WeeklySync.gs`/`EditSync.gs`/`Triggers.gs`の4分割と`コード.gs`の単一ファイルは中身が重複しているだけで、同時に使う必要はない。GASプロジェクトにファイルを分けて置くなら前者4つを、1ファイルで完結させたいなら`コード.gs`のみを使う。**同一プロジェクト内で両方を貼り付けると`CONFIG`などが二重定義されエラーになるので注意。**

**編集時トリガー(`onEdit`)を動作させるには、このスクリプトを「31期予材リスト」スプレッドシートのコンテナバインド型スクリプトとして設置する必要があります**（スプレッドシートを開いた状態で「拡張機能 > Apps Script」からエディタを開く）。スタンドアロン型のプロジェクトでは`onEdit`シンプルトリガーは発火しません。

## 処理内容

1. `SOURCE_FOLDER_ID` フォルダ直下のファイルを走査する。対象はGoogleスプレッドシートおよびExcel(.xlsx/.xls)。ANDPAD出力ファイルはmimeTypeが正しく設定されないことがあるため、mimeTypeで判定できない場合はファイル名の拡張子でもフォールバック判定する。
2. Excelファイルは **手動変換不要・外部API呼び出し不要** で読み取る。ANDPAD等の出力は「拡張子は.xlsxだが中身が標準ZIPではない」ことがあるため、ファイル先頭のマジックバイトで実体を判別し、以下の順にフォールバックする。
   1. **本物の.xlsx(ZIP構造)**: `.xlsx`の実体はZIPアーカイブなので、GAS標準の`Utilities.unzip`でXMLを取り出し、同じくGAS標準の`XmlService`でパースして値を抽出する。
   2. **旧形式バイナリ.xls(OLE構造)**: パースできないため、「.xlsxで保存し直してください」という明確なエラーメッセージを出して`エラー`フォルダへ移動する。
   3. **HTMLテーブルを.xlsx/.xlsとして出力しているケース**: 内容が実はHTMLと判定できた場合、`<table>`をHTMLとして解析して値を抽出する（複数`<table>`がある場合は行数が最も多いものを本体とみなす。Shift_JIS系のcharset宣言があれば自動でその文字コードとして読み直す）。

   Advanced Drive Service・UrlFetchApp・Drive REST APIなど、Driveの外部変換処理は一切使わない。**なお「DriveAppで一時的にGoogleスプレッドシート形式に変換する」処理自体はGASに存在しない**（フォーマット変換ができるのはDrive APIのみで、それは上記の理由により使わない方針としている）。そのため上記3パターンのいずれにも当てはまらない、完全に破損した/未知の形式のファイルは読み取れず、明確なエラーメッセージとともに`エラー`フォルダへ移動される。
3. 列は **ヘッダー名でマッチング** して「週次報告記録」シートに書き込む。ANDPAD側で列の並び順が変わったり、新しい列が追加されたりしても、既存の列名と一致するものは対応する列にそのまま入り、未知の列名が来た場合はシートのヘッダーに自動で追加される（「フォーマットの揺れ」への対応）。取込日時・元ファイル名は常に先頭2列に入る。
4. 追記が終わったファイルは `処理済み` サブフォルダへ移動し、次回以降のスキャン対象から除外することで二重処理を防止する。同名ファイルが既に `処理済み` にある場合（ANDPADが毎回同じファイル名で出力するケースを想定）はタイムスタンプを付けてリネームしてから移動するため、上書き・混同は起きない。
5. 追記が完了した時点でファイルIDをスクリプトプロパティに記録する。仮にその後の「処理済みフォルダへの移動」が失敗しても、次回実行時は記録済みIDのファイルを再追記せずスキップし、移動だけを再試行する（二重処理防止の保険）。
6. 読み取りや書き込みに失敗したファイルは `エラー` サブフォルダへ移動し、`NOTIFY_EMAIL` を設定していればエラー内容をメール通知する。
7. 1件以上のファイルを処理した場合、最後に「報告日」列で昇順ソートし、シート全体のデータから算出した**対象期間**を表す区切り行を先頭(2行目)に挿入し直す。詳細は後述の「報告日順の自動ソートと対象期間の区切り行」を参照。

`処理済み`・`エラー` フォルダは `SOURCE_FOLDER_ID` の直下に初回実行時に自動作成されます。

## 報告日順の自動ソートと対象期間の区切り行

`syncWeeklyReports` が1件以上のファイルを処理した場合、最後に以下の3ステップを実行する。

1. **`removeExistingPeriodSeparatorRows_`**: シート上に残っている対象期間の区切り行(A列が`PERIOD_SEPARATOR_PREFIX`で始まる行)をすべて削除する。
2. **`sortWeeklyReportByReportDate_`**: 「週次報告記録」の**2行目以降**を「報告日」列で**昇順**（古い日付が上）に並べ替える。ソート列は、ヘッダー行から `Config.gs` の `REPORT_DATE_COLUMN_CANDIDATES`（既定:「報告日」→「日付」→「対象日」→「実施日」→「報告日時」→「登録日」の順）に一致する列を探して使う。どれも見つからない場合は `REPORT_DATE_FALLBACK_COLUMN`（既定: 9列目 = I列）を使う。
3. **`insertPeriodSummaryRow_`**: シート全体のデータ(2行目以降)から**対象期間**を算出し、以下のような**区切り行**を**先頭(2行目)に1行だけ**挿入する。

   | A列 | B列以降 |
   | --- | --- |
   | `【対象期間：2026/07/25 〜 2026/07/31】` | (すべて空欄) |

   対象期間は、まず「報告日」列(上記2と同じ列)の値の最小値・最大値から判定する。その列が見つからない・値が判定できない場合は、「元ファイル名」列に含まれる日付(ファイル名パターン、例: `報告一覧_20260720_20260726.xlsx`)からフォールバックする。どちらからも判定できない場合は「不明」(`Config.gs` の `PERIOD_UNKNOWN_LABEL`)と表示する。

   算出した最小値・最大値はそのまま使わず、毎週金曜日に報告を締める運用にあわせて、**開始日はその日が属する週の土曜日まで遡り、終了日はその日が属する週の金曜日まで繰り越して**表示する（`getSaturdayOfWeek_` / `getFridayOfWeek_`、週は土曜始まり・金曜終わり）。例えばデータ内の日付が `2026/07/28`〜`2026/07/30`（火〜木）の場合、対象期間は `2026/07/25 〜 2026/07/31`（土〜金）と表示される。

区切り行は見出しとして視認しやすいよう、**A列からX列(24列目)までをセル結合**し、**背景色**（既定: `#f3f3f3`、`Config.gs` の `PERIOD_SEPARATOR_BACKGROUND_COLOR`）と**太字**で装飾される。結合・装飾はこの区切り行1行にのみ適用され、データ行の書き込み列数には影響しない。結合に必要な列数がシートに無い場合は自動で列を追加する。結合する列数は `Config.gs` の `PERIOD_SEPARATOR_MERGE_COLUMNS`、ラベルの接頭辞・接尾辞は `PERIOD_SEPARATOR_PREFIX` / `PERIOD_SEPARATOR_SUFFIX` で変更できる。

**区切り行は常にシート全体で1行だけ**であり、新しいファイルを取り込むたびに(1)削除→(2)ソート→(3)全データから再算出して先頭へ再挿入、という流れで作り直される。そのため、複数の区切り行が並んだり、ソート後に区切り行が末尾へ移動したりすることはなく、常に「2行目=対象期間の区切り行、3行目以降=報告日順に並んだ全データ」という構成が保たれる。

**「週次報告記録」のヘッダー行に「対象期間」列(データ列)は作成・追記しない。** 以前のバージョンで作成済みの「対象期間」列がヘッダーに残っている場合、そこには新たな値は書き込まれなくなる（不要であれば手動で削除してよい）。「今月」シート編集時の自動転記（onEdit）では区切り行の削除・再挿入は行わない（区切り行の再構築は `syncWeeklyReports` 実行時のみ）。

## 編集時トリガー（見込確度の変更を自動転記）

「今月」という文字列を含むシート名（例: `2026年7月_今月`）の **5行目以降・O列（15列目, 見込確度）** の変更を検知し、以下の2箇所へ自動的に1行追記する。

- **週次報告記録**: 編集された行を、「今月」シートのヘッダー行（既定: 4行目、`Config.gs` の `EDIT_HEADER_ROW` で調整）の列名とマッチングして追記する（週次自動転記と同じ列マッチング機構を再利用）。「元ファイル名」列には `(シート編集) シート名` が入る。
- **週次ステータス変更履歴**: `変更日時 / シート名 / 案件名 / 列名 / 変更前 / 変更後 / 編集者 / 識別情報` を1行追記する。「案件名」列（既定: C列、`STATUS_HISTORY_PROJECT_COLUMN`）には、「今月」タブの `EDIT_URL_COLUMN`（既定: H列。案件名テキスト+ハイパーリンク）のリッチテキストがそのままコピーされ、案件名の表示とリンク先が常に一致する。「識別情報」は対象行の1列目〜14列目（`EDIT_IDENTIFIER_COLUMN_COUNT`）のうち空でない値を` / `区切りで連結したもの（案件名・得意先名などを想定）。

### 動作条件・注意点

- **この機能は `onEdit(e)` シンプルトリガーとして実装されているため、スクリプトを「31期予材リスト」スプレッドシートのコンテナバインド型として設置している場合のみ動作する。** スタンドアロン型プロジェクトでは発火しない。
- 範囲コピー&ペーストなど複数セルを一括編集した場合も、O列を含む範囲であれば対象行すべてを処理する（1回の編集イベントで処理する行数の上限は `EDIT_MAX_ROWS_PER_EVENT`、既定300行超は超過分を切り捨てログ出力）。
- 「今月」シートの実際のレイアウト（ヘッダー行の位置、識別情報として使う列数、案件名+URL列）は環境によって異なるため、`Config.gs` の `EDIT_HEADER_ROW` / `EDIT_IDENTIFIER_COLUMN_COUNT` / `EDIT_MIN_ROW` / `EDIT_TARGET_COLUMN` / `EDIT_URL_COLUMN` を実際のシート構成に合わせて調整すること。
- より強い権限（メール送信等）が必要な場合は、`installEditTrigger()` を一度実行することで `handleEdit_` をインストーラブルトリガーとして登録できる（任意、シンプルトリガーの `onEdit` と併用可）。

### 「週次ステータス変更履歴」の案件名ハイパーリンク

「今月」タブの `EDIT_URL_COLUMN`（既定: H列）には、案件名テキストにURLへのハイパーリンクが設定されている。この機能は、その表示文字列＋リンクURLを「週次ステータス変更履歴」の `STATUS_HISTORY_PROJECT_COLUMN`（既定: C列、案件名）へ自動的にコピーする。

- **新規行への自動セット**: O列（見込確度）編集時に `appendStatusHistory_` が新しい行を追記した直後、同じ行の「今月」タブH列のリッチテキストをそのままコピーする（`copyProjectHyperlink_`）。手作業は不要。
- **「週次ステータス変更履歴」のC列を手動で入力・更新した場合**: `onEdit` が検知し、「今月」タブのH列と案件名テキストが完全一致する行を探して、そのハイパーリンクを自動でセットする（`handleStatusHistoryProjectEdit_`）。一致しない場合は何もしない。
- **既存のリンクなしセルへの一括適用**: `applyProjectLinksToStatusHistory()` をGASエディタから手動実行すると、「週次ステータス変更履歴」のC列のうちまだリンクが設定されていないセルすべてに対して、「今月」タブとの案件名テキスト一致でハイパーリンクを設定する（既にリンク済みのセルはスキップするため、何度でも再実行できる）。
- 案件名の一致は完全一致（前後の空白をトリムしたうえで）。表記ゆれがあると一致しない点に注意。
- 案件名が「今月」タブ内で重複している場合は、最後に見つかった行の値を採用する。

## セットアップ手順

**Advanced Serviceの追加もマニフェストの特別な設定も不要です。** DriveApp・SpreadsheetApp・Utilities・XmlServiceはすべてGASの標準サービスで、有効化操作は要りません。`appsscript.json`はタイムゾーン設定程度のシンプルな内容です。

### 単一ファイル版（`コード.gs`）を使う場合（迷ったらこちら）

1. **「31期予材リスト」スプレッドシートを開いた状態で「拡張機能 > Apps Script」からエディタを開く**（コンテナバインド型として作成する）。編集時トリガー(`onEdit`)は「今月」シートと同じスプレッドシートに紐づいたスクリプトでないと発火しないため、スタンドアロン型プロジェクトは使わないこと。
2. デフォルトで存在する「コード.gs」を開き、**中身を全選択して一度すべて削除**してから、この`コード.gs`の内容を丸ごと貼り付ける（既存コードの一部が残っていると構文エラーの原因になるため、必ず全削除してから貼り付けること）。
3. エディタ上部の関数選択で `syncWeeklyReports` を選び、一度手動実行して権限承認（Drive・スプレッドシートへのアクセス許可）を行う。
4. 実行ログ (表示 → 実行数、またはログ) で正常終了・追記結果を確認する。
5. 「今月」シートのO列（見込確度）を試しに編集し、「週次報告記録」「週次ステータス変更履歴」に行が追記されることを確認する（onEditは1〜2の権限承認後、シートを再読み込みすれば有効になる）。

### 分割ファイル版（`Config.gs`/`WeeklySync.gs`/`EditSync.gs`/`Triggers.gs`）を使う場合

1. 上記1と同様に、「31期予材リスト」スプレッドシートのコンテナバインド型としてプロジェクトを作成する。
2. `Config.gs` / `WeeklySync.gs` / `EditSync.gs` / `Triggers.gs` の内容をそれぞれ同名のスクリプトファイルとして貼り付ける（デフォルトの「コード.gs」は削除するか空にしておく）。
3. 上記の3〜5と同様の手順（手動実行 → 権限承認 → ログ確認 → onEdit動作確認）を行う。

## 週次トリガーの設定手順（`syncWeeklyReports` を毎週月曜6時〜7時に実行）

### 方法A: GASエディタから手動設定（推奨）

1. エディタ左メニューの時計アイコン「トリガー」を開く。
2. 右下「トリガーを追加」をクリック。
3. 以下を設定して保存する。
   - 実行する関数を選択: `syncWeeklyReports`
   - 実行するデプロイを選択: `Head`
   - イベントのソースを選択: `時間主導型`
   - 時間ベースのトリガーのタイプを選択: `週タイマー`
   - 曜日を選択: `月曜日`
   - 時刻を選択: `午前6時〜7時`
4. 保存すると一覧に週次トリガーが表示される。

### 方法B: スクリプトから設定

エディタ上部の関数選択で `installWeeklyTrigger` を選び、一度実行する。
毎週月曜6時台（6時〜7時の間）に `syncWeeklyReports` を実行するトリガーが作成される（既存の同名トリガーがあれば作り直される）。
曜日・時刻を変えたい場合は `Triggers.gs`（または`コード.gs`内の同関数）の `onWeekDay(...)` / `atHour(...)` を編集する。

編集時トリガー(`onEdit`)はシンプルトリガーのため、上記のような個別設定は不要（コンテナバインド型として設置していれば自動的に有効）。より強い権限が必要な場合のみ、`installEditTrigger` を実行してインストーラブルトリガーを追加設定する。

## 補足・前提条件

- 取り込むのは各ファイルの **1シート目のみ**。複数シートを取り込みたい場合は `appendFileToTargetSheet_` / `readXlsxAsValues_` を修正してループさせる。
- 対応形式は **.xlsx(ZIP構造)・HTMLテーブル(拡張子だけ.xlsx/.xlsのケースを含む)** の2種類。旧形式のバイナリ.xls(Excel 97-2003, OLE構造)は読み取れず、エラーとして`エラー`フォルダへ移動される。ANDPADから.xls形式で出力される場合は、事前に.xlsxで保存し直すか、ANDPAD側の出力設定を確認すること。
- HTMLテーブルとして読み取る場合、複数の`<table>`がある中から行数最多のものを自動選択するが、レイアウト目的の入れ子テーブル構成によっては意図しないテーブルが選ばれる可能性がある。その場合は`readValuesFromHtmlTable_`のテーブル選択ロジックを対象ファイルの実際の構造に合わせて調整すること。
- **日付・数値の書式は反映されない。** セルの生の値（文字列/数値/真偽値）をそのまま読み取るため、日付書式が設定されたセルはExcel内部のシリアル値（例: `45123`）としてそのまま入る。日付として扱いたい場合は、取り込み後にスプレッドシート側で書式設定するか、`extractCellValue_`にシリアル値→Dateの変換を追加する。
- 列はヘッダー名（1行目）でマッチングするため、ANDPAD側で列順が変わったり列が増えたりしても正しい列に入る。表記ゆれ（例:「初回接触日」と「アプローチ日」など別名扱い）は `Config.gs` の `STAGE_COLUMN_ALIASES` に登録した項目のみ自動で正規化される（`resolveCanonicalHeader_`）。それ以外の列は表記ゆれを自動判定しないため、必要なら `STAGE_COLUMN_ALIASES` に別名を追加するか、同様のエイリアス変換表を追加する。
- CVR(コンバージョンレート)集計用に、`案件種別` / `属性` / `アプローチ日` / `面談日` / `見積日` / `契約日` の6列は `syncWeeklyReports` 実行時に必ずシート上へ存在するよう自動追加される（今回のファイルに該当列が無くても列自体は作られ、値は空欄のまま）。集計方法・数式例は `CVR_KPI_DESIGN.md` を参照。
- `Config.gs` の `SOURCE_HAS_HEADER` が `false` の場合は「列1」「列2」...という仮のヘッダー名で取り込む（フォーマット変動への耐性は下がる）。
- `Config.gs` の `NOTIFY_EMAIL` にメールアドレスを設定すると、処理失敗時のみ通知メールが届く。
- 処理済みファイルIDの記録（スクリプトプロパティ `PROCESSED_FILE_IDS`）は直近 `PROCESSED_LOG_MAX` 件のみ保持する。件数を増減したい場合は `Config.gs` を編集する。
- 報告日順ソート・対象期間の算出に使う列名の候補とフォールバック列番号は `Config.gs` の `REPORT_DATE_COLUMN_CANDIDATES` / `REPORT_DATE_FALLBACK_COLUMN` で変更できる。区切り行のラベル文言は `PERIOD_SEPARATOR_PREFIX` / `PERIOD_SEPARATOR_SUFFIX` / `PERIOD_UNKNOWN_LABEL`、結合列数・背景色は `PERIOD_SEPARATOR_MERGE_COLUMNS` / `PERIOD_SEPARATOR_BACKGROUND_COLOR` で変更できる。
- 「週次報告記録」シートへ転記する列数の上限は `Config.gs` の `MAX_DATA_COLUMNS`（既定: 30列目 = AD列。ANDPAD側の元24列 + CVR集計用6列分の余裕）。**上限を超える列は転記対象外**で、ヘッダー追加・値の書き込みのどちらも行われない（`ensureColumnsExist_` / `appendFileToTargetSheet_` / `appendEditToWeeklyReport_` で共通して適用）。転記したい列を増やしたい場合はこの値を変更する（区切り行の結合列数 `PERIOD_SEPARATOR_MERGE_COLUMNS` もこの値に合わせて変更すること）。
- 編集時トリガーの監視条件（シート名キーワード・開始行・対象列・ヘッダー行・識別列数・1回あたりの最大処理行数・ステータス変更履歴シート名）はすべて `Config.gs` の `EDIT_SHEET_NAME_KEYWORD` / `EDIT_MIN_ROW` / `EDIT_TARGET_COLUMN` / `EDIT_HEADER_ROW` / `EDIT_IDENTIFIER_COLUMN_COUNT` / `EDIT_MAX_ROWS_PER_EVENT` / `STATUS_HISTORY_SHEET_NAME` で変更できる。

## トラブルシューティング

- **`TypeError: Drive.Files.create is not a function` / `Bad Request` (Drive.Files.insert)**: いずれも過去のバージョンでAdvanced Drive Service経由のExcel変換を使っていた際に、GASエディタの「サービス」で追加したバージョン(v2/v3)やAPIの呼び出し方の不一致で発生していたエラー。現在のコードはAdvanced Drive Service・Drive REST API・UrlFetchAppを一切使わず、`Utilities.unzip`と`XmlService`だけで.xlsxを直接パースするため、これらのエラーは原理的に発生しない。
- **`Exception: Service Spreadsheets failed while accessing document with id ...`**: 対象ファイルのmimeTypeが`application/vnd.google-apps.spreadsheet`(Googleスプレッドシート)と判定されたにもかかわらず、そのIDをGoogleスプレッドシートとして開けなかった場合に発生する。多くの場合、GAS側のコードが最新版に更新されておらず、貼り付け時にコードの一部が古いまま残っている（後述の構文エラーと同根の問題）。まずコード全体を最新版で完全に置き換えてから再実行すること。
- **コード末尾に余計な記号や関数の重複が混入し保存できない**: チャットの表示上は問題なくても、コピー範囲や貼り付けタイミングによって末尾に余分な文字が残ることがある。対処手順:
  1. GASエディタで対象ファイルを開き、`Ctrl+A`（Mac: `Cmd+A`）で全選択して`Delete`し、**空になったことを目視で確認**する。
  2. このリポジトリの`コード.gs`をテキストエディタ等で開いて中身を全コピーし、貼り付ける。
  3. 貼り付け後、`Ctrl+End`でファイル末尾へ移動し、`}`の後に何も残っていないか目視確認する。
  4. それでも解消しない場合は、GASプロジェクトを一度削除して新規プロジェクトを作り直すか、Node.js環境があれば[clasp](https://github.com/google/clasp)でこのリポジトリのファイルを直接pushする方法が最も確実（コピー&ペーストの手順自体を経由しないため）。
