# CVR(コンバージョンレート)KPI 集計・可視化 設計案

対象: 「31期予材リスト」スプレッドシート > `週次報告記録` シート / `コンバージョンレート` シート

## 結論

- CVR集計はANDPAD報告画面の **4ステータス**「アプローチ」「面談」「提案（見積提示）」「契約」を基準とする。
- `週次報告記録`(生データ)に **段階到達日** 4列（アプローチ日/面談日/提案日/契約日）を追加する。
  - 現状の「ステータス」1列（現在の最新状態のみ保持）方式だと、契約まで進んだ案件は「提案」のカウントから漏れてCVRが不正確になるため。
- 「案件種別」は、入力規則で定義されている **15カテゴリ**（「風力」を除く）を、案件(引合)名のテキストから`classifyCategory_`で自動判定して格納する。該当キーワードが無い場合は「その他」。
- 生データはそのまま集計に使わず、新規シート `コンバージョンレート` を追加し、そこに COUNTIFS ベースの集計表を作る（生データを直接いじらない = ANDPAD自動追記との衝突を避ける）。
- 全体集計、15カテゴリ別（案件種別）・属性別・**担当者別**（`週次報告記録`の「氏名」列基準）集計を同一シート内に並べ、期間セル(開始/終了日)を変えるだけで再計算される構成にする。担当者別は一覧表(`UNIQUE`展開)・ドロップダウン切替・主要メンバー固定行展開の3案を用意（6節）。
- **実装済み**:
  - `Config.gs`(`STAGE_COLUMN_ALIASES`) + `WeeklySync.gs`(`resolveCanonicalHeader_` / `ensureColumnsExist_` / `getTargetSheet_`) で、ANDPAD側の表記ゆれ（「提案（見積提示）」の全角/半角カッコ違いや「見積日」表記など）を正規化のうえ、6列（案件種別/属性/アプローチ日/面談日/提案日/契約日）を`syncWeeklyReports`実行時に必ず存在させる。
  - `Config.gs`(`CATEGORY_RULES` / `CATEGORY_FALLBACK` / `PROJECT_NAME_COLUMN_CANDIDATES`) + `WeeklySync.gs`(`classifyCategory_`) で、「案件（引合）名」列のテキストから「案件種別」を自動判定する。
  - `コード.gs`（単一ファイル版）にも同内容を反映済み。

---

## 0. 算出するCVR（ANDPAD報告画面の4ステータス基準）

| # | CVR | 計算式 |
| --- | --- | --- |
| ① | アプローチ → 面談 CVR | 面談数 ÷ アプローチ数 |
| ② | 面談 → 提案（見積提示） CVR | 提案数 ÷ 面談数 |
| ③ | 提案（見積提示） → 契約 CVR | 契約数 ÷ 提案数 |

## 1. `週次報告記録` 側の追加列（実装済み）

既存列（取込日時, 元ファイル名, ...案件情報...）はそのまま。末尾に以下を追加:

| 列名 | 内容 |
| --- | --- |
| 案件種別 | `classifyCategory_`が案件(引合)名から自動判定した15カテゴリのいずれか(下表参照)。未判定は「その他」 |
| 属性 | 例: 紹介 / 反響 / 法人 など |
| アプローチ日 | ANDPAD「アプローチ」ステータスに到達した日。未到達なら空欄 |
| 面談日 | ANDPAD「面談」ステータスに到達した日。未到達なら空欄 |
| 提案日 | ANDPAD「提案（見積提示）」ステータスに到達した日。未到達なら空欄 |
| 契約日 | ANDPAD「契約」ステータスに到達した日。未到達なら空欄 |

**列位置**:
- 未使用の新規シート（`getTargetSheet_`が初回作成する場合）は必ず A=取込日時, B=元ファイル名, C=案件種別, D=属性, E=アプローチ日, F=面談日, G=提案日, H=契約日 の順で作られる。
- 既に運用中の`週次報告記録`（今回のケース）は、次回`syncWeeklyReports`実行時に不足している6列が**既存ヘッダーの末尾**に自動追加される（既存列の並びは変更しない）。実行後にシートの1行目を確認し、実際に追加された列アルファベットを本ドキュメントのC〜Hの代わりに読み替えること。
- ANDPAD側の項目名が`STAGE_COLUMN_ALIASES`(`Config.gs`)の別名リストに一致しない場合は正規化されず、元の項目名のまま別列として追加されるので、実際の出力を確認して別名リストに追記する運用とする。「提案（見積提示）」は`提案日`列に正規化される。登録済みの別名: `提案日` / `提案（見積提示）` / `提案(見積提示)` / `提案（見積提示）日` / `提案(見積提示)日` / `見積日` / `見積提出日` / `御見積日` / `見積書提出日` / `提案書提出日`。

### 案件種別の自動判定ルール（`Config.gs` の `CATEGORY_RULES`）

「案件（引合）名」列（`PROJECT_NAME_COLUMN_CANDIDATES`: `案件（引合）名` / `案件(引合)名` / `案件名` / `引合名` / `案件名称` のいずれかに一致する列）のテキストを、以下の順でキーワード走査し、最初に一致したカテゴリを採用する（`classifyCategory_`）。

| 判定順 | カテゴリ | 主なキーワード例 |
| --- | --- | --- |
| 1 | 事業者用PV | 事業者用PV / 事業用PV / 産業用PV |
| 2 | リパワリング | リパワリング / リパワー |
| 3 | 事業者PCS交換 | 事業者PCS交換 / 事業用PCS交換 / 産業用PCS交換 |
| 4 | リプレイス | リプレイス |
| 5 | 事業者用創蓄 | 事業者用創蓄 / 事業用創蓄 / 産業用創蓄 |
| 6 | 住宅用PV | 住宅用PV |
| 7 | 住宅用創蓄 | 住宅用創蓄 / 住宅用蓄電池 |
| 8 | EV充放電システム | EV充放電システム / EV充放電 |
| 9 | 戸建てPCS交換 | 戸建てPCS交換 / 戸建PCS交換 |
| 10 | EQ/オール電化 | EQ/オール電化 / オール電化 / EQ |
| 11 | O&M | O&M（全角/半角バリエーション込み） |
| 12 | メンテナンス | メンテナンス / メンテ |
| 13 | LED'S | LED'S / LEDS |
| 14 | 行政案件 | 行政案件 / 行政 |
| 15 | その他 | (どれにも一致しない場合の既定値、`CATEGORY_FALLBACK`) |

「風力」は入力規則の選択肢から除外されているため、判定ルールにも含めない。実際のANDPAD案件名の表記に合わせて`CATEGORY_RULES`のkeywordsを随時追加・調整すること（`STAGE_COLUMN_ALIASES`と同じ運用パターン）。

## 3. 数式（全体集計、B1/B2=期間開始・終了、新規シート想定の列: E=アプローチ日,F=面談日,G=提案日,H=契約日）

```
アプローチ件数: =COUNTIFS(週次報告記録!$E:$E, ">="&$B$1, 週次報告記録!$E:$E, "<="&$B$2)
面談件数     : =COUNTIFS(週次報告記録!$F:$F, ">="&$B$1, 週次報告記録!$F:$F, "<="&$B$2)
提案件数     : =COUNTIFS(週次報告記録!$G:$G, ">="&$B$1, 週次報告記録!$G:$G, "<="&$B$2)
契約件数     : =COUNTIFS(週次報告記録!$H:$H, ">="&$B$1, 週次報告記録!$H:$H, "<="&$B$2)

①アプローチ→面談CVR      : =IFERROR(面談件数セル / アプローチ件数セル, "")
②面談→提案(見積提示)CVR   : =IFERROR(提案件数セル / 面談件数セル, "")
③提案(見積提示)→契約CVR   : =IFERROR(契約件数セル / 提案件数セル, "")
```

※既存シート（今回のケース）は列位置が異なるため、実際に追加された列アルファベットに置き換えること。

## 4. 数式（15カテゴリ別、新規シート想定の列: C=案件種別、$A13=カテゴリ名セル、行13〜27）

```
アプローチ数: =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$E:$E, ">="&$B$1, 週次報告記録!$E:$E, "<="&$B$2)
面談数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$F:$F, ">="&$B$1, 週次報告記録!$F:$F, "<="&$B$2)
提案数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$G:$G, ">="&$B$1, 週次報告記録!$G:$G, "<="&$B$2)
契約数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$H:$H, ">="&$B$1, 週次報告記録!$H:$H, "<="&$B$2)

①アプローチ→面談CVR    : =IFERROR(面談数セル / アプローチ数セル, "")
②面談→提案(見積提示)CVR : =IFERROR(提案数セル / 面談数セル, "")
③提案(見積提示)→契約CVR : =IFERROR(契約数セル / 提案数セル, "")
```

行13〜27をそのまま下にコピーすれば15カテゴリ全行分が完成する（`$A13`が各行のカテゴリ名セルを自動的に指すため、数式自体は全行共通）。

属性別ブロックは `$C:$C`(案件種別列) を `$D:$D`(属性列) に、カテゴリ名セルを属性リストのセルに置き換えるだけで同一パターン。

## 5. 可視化

- ダッシュボード上の「全体」表（件数4行 + CVR%3行）を元に、**棒グラフ(件数) + 折れ線(CVR%)の組み合わせグラフ**を挿入。
- 15カテゴリ別表は**横棒グラフ**でカテゴリ間のCVR%比較を可視化（0件のカテゴリも常に表示されるため、比較しやすい）。
- 週推移を見たい場合は、B1/B2に週の開始/終了を入れて同じ数式を1週間ごとにコピーした「週次推移表」を別ブロックに用意し、折れ線グラフで時系列表示（QUERYで自動生成も可だが、まずはCOUNTIFSの手動コピーで十分運用可能）。

## 6. 担当者別集計テーブル（`週次報告記録` の「氏名」列基準）

案件種別・属性と同じCOUNTIFSパターンで、条件列を「氏名」に差し替えるだけで担当者別CVRを算出できる。担当者名の取得方法として、用途に応じて3案を使い分ける。以下の数式は氏名列を仮に`I列`とする（実際の列アルファベットに置き換えること。「氏名」はSTAGE_COLUMN_ALIASESの対象外でANDPAD側の値がそのまま入るため、列位置はANDPAD出力に依存する）。

### 案A: 一覧表形式（`UNIQUE`展開、全担当者のランキング表示向け）

```
31 【担当者別】
32 氏名           アプローチ  面談  提案(見積提示)  契約  ①面談CVR  ②提案CVR  ③契約CVR
33 =UNIQUE(...)    ...
34 (以下スピル)
```

- A33: `=UNIQUE(週次報告記録!$I2:$I)`。空欄や見出し行の混入を避けたい場合は
  `=SORT(UNIQUE(FILTER(週次報告記録!$I2:$I, 週次報告記録!$I2:$I<>"")))` のように空欄除外・並べ替えを追加する。
- B33〜H33に下記の数式を入れてA33からのスピル範囲ぶんだけ下にコピーすれば、担当者の増減に自動追従する。

```
アプローチ数: =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$E:$E, ">="&$B$1, 週次報告記録!$E:$E, "<="&$B$2)
面談数     : =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$F:$F, ">="&$B$1, 週次報告記録!$F:$F, "<="&$B$2)
提案数     : =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$G:$G, ">="&$B$1, 週次報告記録!$G:$G, "<="&$B$2)
契約数     : =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$H:$H, ">="&$B$1, 週次報告記録!$H:$H, "<="&$B$2)

①アプローチ→面談CVR    : =IFERROR(面談数セル / アプローチ数セル, "")
②面談→提案(見積提示)CVR : =IFERROR(提案数セル / 面談数セル, "")
③提案(見積提示)→契約CVR : =IFERROR(契約数セル / 提案数セル, "")
```

### 案B: ドロップダウン切替形式（個人別スコアカード、1on1向け）

```
36 担当者選択: [▼ドロップダウン]
37
38 【選択した担当者の全体CVR】
39              件数         CVR%
40 アプローチ    =件数式      -
41 面談         =件数式      =B41/B40
42 提案(見積提示) =件数式      =B42/B41
43 契約         =件数式      =B43/B42
```

- B36セルに「データの入力規則 > リストを範囲で指定」を設定し、範囲に案Aの氏名一覧(`$A$33:$A`)を指定してプルダウン化する。
- B40〜B43の数式は案Aと同じCOUNTIFSで、条件セルを`$A33`(行ごとの氏名)から`$B$36`(選択中の担当者)に差し替えるだけ:
  `=COUNTIFS(週次報告記録!$I:$I, $B$36, 週次報告記録!$E:$E, ">="&$B$1, 週次報告記録!$E:$E, "<="&$B$2)` （面談/提案/契約も同様に列だけ差し替え）。
- 全員を横並びで比較したい時は案A、特定の1人を深掘りしたい時（1on1・週次面談等）は案Bが向いている。同一シートに両方併設しても数式は競合しない。

### 案C: 主要メンバー固定行展開

- 人数が少ない、または特定の主要メンバーだけを常に追いたい場合は、案Aの`UNIQUE`の代わりにA33以降へ氏名を手入力で固定する（15カテゴリ別ブロックと同じ「固定リスト」パターン）。数式は案Aと同一。異動等で担当者が変わった際は手動更新が必要になる点のみ案Aと異なる。

## 前提・注意

- 列の自動追加・表記ゆれ正規化・案件種別の自動判定は`syncWeeklyReports`実行時のみ行われる。導入後、最初の週次実行が終わってから`週次報告記録`の1行目を確認し、本ドキュメントの数式内の列アルファベットを実際の列位置に合わせて修正すること。
- 「提案日」「契約日」等の段階日付列に対応するANDPAD側の項目名が`Config.gs`の`STAGE_COLUMN_ALIASES`に登録されていない場合、正規化されず別列として追加される。ANDPAD側の実際の出力ヘッダーを確認し、必要な別名を`STAGE_COLUMN_ALIASES`に追加すること。
- ANDPAD側にそもそも段階日付の項目が存在しない場合（現在ステータスのみ管理している等）は、ANDPAD側に項目追加を依頼するか、当該シートで手動運用（ステータス更新時に日付を都度記入）する運用ルールが必要。現状のスクリプトはANDPAD由来のデータをそのまま転記するのみで、ステータス値から日付を自動生成する処理は行っていない。
- `classifyCategory_`は案件(引合)名の文字列に対する単純なキーワード部分一致であり、`CATEGORY_RULES`に登録した文言が実際の案件名に含まれていなければ「その他」に分類される。運用開始後、「その他」に分類された件数が多い場合はANDPAD側の実際の命名パターンを確認し、`CATEGORY_RULES`のkeywordsを追加すること。
- 「案件（引合）名」に対応する列がANDPAD側に無い(`PROJECT_NAME_COLUMN_CANDIDATES`のいずれにも一致しない)場合、案件種別の自動判定は行われず、その回の取り込みでは「案件種別」列は空欄のままになる。
- 「氏名」列はSTAGE_COLUMN_ALIASESの対象外で、ANDPAD側の値がそのまま転記される。表記ゆれ（全角/半角スペースの有無、姓名の区切り方の違いなど）があると、`UNIQUE`が同一人物を別の担当者として分けてしまう場合がある。気になる場合は氏名列に対して`TRIM`前処理を挟むか、`STAGE_COLUMN_ALIASES`と同様の正規化ルールをスクリプト側に追加することを検討する。
