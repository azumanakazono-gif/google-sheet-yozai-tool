# CVR(コンバージョンレート)KPI 集計・可視化 設計案

対象: 「31期予材リスト」スプレッドシート > `週次報告記録` シート / `コンバージョンレート` シート

## 結論

- CVR集計はANDPAD報告画面の **4ステータス**「アプローチ」「面談」「提案（見積提示）」「契約」を基準とする。
- `週次報告記録`(生データ)に **段階到達日** 4列（アプローチ日/面談日/提案日/契約日）を追加する。
  - 現状の「ステータス」1列（現在の最新状態のみ保持）方式だと、契約まで進んだ案件は「提案」のカウントから漏れてCVRが不正確になるため。
- 「案件種別」は、入力規則で定義されている **15カテゴリ**（「風力」を除く）を、案件(引合)名のテキストから`classifyCategory_`で自動判定して格納する。該当キーワードが無い場合は「その他」。
- 生データはそのまま集計に使わず、新規シート `コンバージョンレート` を追加し、そこに COUNTIFS ベースの集計表を作る（生データを直接いじらない = ANDPAD自動追記との衝突を避ける）。
- 期間の絞り込みは**方法2(開始日・終了日を任意指定)**を採用する。B2(開始日)・D2(終了日)に日付を手入力すると、その期間だけが全体・15カテゴリ別・属性別・担当者別のCOUNTIFSに反映される。**B2・D2は空欄可で、空欄側は「全期間」扱い**になる（2節）。
- 全体集計、15カテゴリ別（案件種別）・属性別・**担当者別**（`週次報告記録`の「氏名」列基準）集計を同一シート内に並べ、この期間セルを変えるだけで再計算される構成にする。担当者別は一覧表(`UNIQUE`展開)・ドロップダウン切替・主要メンバー固定行展開の3案を用意（6節）。
- 単発の期間集計だけでなく、**月別・週別の時系列**でも絞り込み・展開できるよう、月(または週)リスト×カテゴリ/担当者リストをINDEX/MODで自動生成するロング形式テーブルと、月選択ドロップダウン+`FILTER`(またはスライサー)による絞り込みの構成案を用意する（7節）。
- **実装済み**:
  - `Config.gs`(`STAGE_COLUMN_ALIASES`) + `WeeklySync.gs`(`resolveCanonicalHeader_` / `ensureColumnsExist_` / `getTargetSheet_`) で、ANDPAD側の表記ゆれ（「提案（見積提示）」の全角/半角カッコ違いや「見積日」表記など）を正規化のうえ、6列（案件種別/属性/アプローチ日/面談日/提案日/契約日）を`syncWeeklyReports`実行時に必ず存在させる。
  - `Config.gs`(`CATEGORY_RULES` / `CATEGORY_FALLBACK` / `PROJECT_NAME_COLUMN_CANDIDATES`) + `WeeklySync.gs`(`classifyCategory_`) で、「案件（引合）名」列のテキストから「案件種別」を自動判定する。
  - `コード.gs`（単一ファイル版）にも同内容を反映済み。

## 0. 算出するCVR（ANDPAD報告画面の4ステータス基準）

| # | CVR | 計算式 |
| --- | --- | --- |
| ① | アプローチ → 面談 CVR | 面談数 ÷ アプローチ数 |
| ② | 面談 → 提案（見積提示） CVR | 提案数 ÷ 面談数 |
| ③ | 提案（見積提示） → 契約 CVR | 契約数 ÷ 提案数 |

## 1. `週次報告記録` 側の追加列（実装済み）

既存列（取込日時, 元ファイル名, ...案件情報...）はそのまま。末尾に以下を追加:

| 列名 | 内容 |
| --- | --- |
| 案件種別 | `classifyCategory_`が案件(引合)名から自動判定した15カテゴリのいずれか(下表参照)。未判定は「その他」 |
| 属性 | 例: 紹介 / 反響 / 法人 など |
| アプローチ日 | ANDPAD「アプローチ」ステータスに到達した日。未到達なら空欄 |
| 面談日 | ANDPAD「面談」ステータスに到達した日。未到達なら空欄 |
| 提案日 | ANDPAD「提案（見積提示）」ステータスに到達した日。未到達なら空欄 |
| 契約日 | ANDPAD「契約」ステータスに到達した日。未到達なら空欄 |

**列位置**:
- 未使用の新規シート（`getTargetSheet_`が初回作成する場合）は必ず A=取込日時, B=元ファイル名, C=案件種別, D=属性, E=アプローチ日, F=面談日, G=提案日, H=契約日 の順で作られる。
- 既に運用中の`週次報告記録`（今回のケース）は、次回`syncWeeklyReports`実行時に不足している6列が**既存ヘッダーの末尾**に自動追加される（既存列の並びは変更しない）。実行後にシートの1行目を確認し、実際に追加された列アルファベットを本ドキュメントのC〜Hの代わりに読み替えること。
- ANDPAD側の項目名が`STAGE_COLUMN_ALIASES`(`Config.gs`)の別名リストに一致しない場合は正規化されず、元の項目名のまま別列として追加されるので、実際の出力を確認して別名リストに追記する運用とする。「提案（見積提示）」は`提案日`列に正規化される。登録済みの別名: `提案日` / `提案（見積提示）` / `提案(見積提示)` / `提案（見積提示）日` / `提案(見積提示)日` / `見積日` / `見積提出日` / `御見積日` / `見積書提出日` / `提案書提出日`。

## 2. `コンバージョンレート` シート レイアウト案

### 2-0. 期間絞り込み（方法2: 開始日・終了日の任意指定）

```
   A         B            C         D
1
2  開始日     2026/07/01   終了日     2026/07/31
3
4  【全体】
5              件数         CVR%
6  アプローチ    =件数式      -
7  面談         =件数式      =B7/B6
8  提案(見積提示) =件数式      =B8/B7
9  契約         =件数式      =B9/B8
11 【案件種別別(15カテゴリ固定)】
12 案件種別        アプローチ  面談  提案(見積提示)  契約  ①面談CVR  ②提案CVR  ③契約CVR
13 事業者用PV       ...
14 リパワリング     ...
15 事業者PCS交換    ...
16 リプレイス       ...
17 事業者用創蓄     ...
18 住宅用PV         ...
19 住宅用創蓄       ...
20 EV充放電システム ...
21 戸建てPCS交換    ...
22 EQ/オール電化    ...
23 O&M              ...
24 メンテナンス     ...
25 LED'S            ...
26 行政案件         ...
27 その他           ...
29 【属性別】（同じ列構成をもう1ブロック。属性は`=UNIQUE(...)`で自動リスト化）
31 【担当者別】（6節参照。UNIQUE展開/ドロップダウン切替/固定行展開の3案）
50+【月別×カテゴリ別】【月別×担当者別】（7節参照。ロング形式+月選択フィルター）
```

- **A2/C2**: 固定ラベル「開始日」「終了日」。**B2/D2**: 期間の開始日・終了日を**手動入力**するセル（日付ピッカーの入力規則を設定してもよい）。
- **B2・D2は空欄可**。片方または両方を空欄にした場合、そちら側は無制限（=全期間扱い）になる。例: B2のみ空欄なら「〜2026/07/31まで全て」、両方空欄なら「全期間」。
- 「案件種別別」ブロックの1列目(A13:A27)は、`Config.gs`の`CATEGORY_RULES`と同じ15カテゴリ名を**手入力で固定**する（属性のように`UNIQUE`で動的リスト化しない。分類が固定15種のため、常に全カテゴリを0件でも表示できるようにするのが狙い）。
- CVR%セルは表示形式を「パーセント」に設定

### 2-1. 実効期間ヘルパーセル（空欄=全期間の吸収）

B2・D2が空欄でもCOUNTIFSの条件式が破綻しないよう、以下の2セルで「実際に絞り込みに使う期間」を計算しておく。以降の3・4・6節の全COUNTIFSは、この2セルだけを参照すればよい構成にする（`IF($B$2="",...)`をCOUNTIFSごとに重複して書かずに済む）。

| セル | 内容 | 数式 |
| --- | --- | --- |
| K1 | ラベル「実効開始日」 | (文字列) |
| K2 | 実効開始日 | `=IF($B$2="",DATE(1900,1,1),$B$2)` |
| L1 | ラベル「実効終了日」 | (文字列) |
| L2 | 実効終了日 | `=IF($D$2="",DATE(2200,12,31),$D$2)` |

B2が空欄ならK2は1900/1/1(データ上あり得ない過去)、D2が空欄ならL2は2200/12/31(データ上あり得ない未来)になり、結果的に「その側は絞り込まない」のと同じ挙動になる。K2/L2は表示上「実効開始日」「実効終了日」として見せてもよいし、行を非表示にしてもよい。

## 3. 数式（全体集計、実効期間=$K$2(実効開始日)・$L$2(実効終了日)、新規シート想定の列: E=アプローチ日,F=面談日,G=提案日,H=契約日）

```
アプローチ件数: =COUNTIFS(週次報告記録!$E:$E, ">="&$K$2, 週次報告記録!$E:$E, "<="&$L$2)
面談件数     : =COUNTIFS(週次報告記録!$F:$F, ">="&$K$2, 週次報告記録!$F:$F, "<="&$L$2)
提案件数     : =COUNTIFS(週次報告記録!$G:$G, ">="&$K$2, 週次報告記録!$G:$G, "<="&$L$2)
契約件数     : =COUNTIFS(週次報告記録!$H:$H, ">="&$K$2, 週次報告記録!$H:$H, "<="&$L$2)

①アプローチ→面談CVR      : =IFERROR(面談件数セル / アプローチ件数セル, "")
②面談→提案(見積提示)CVR   : =IFERROR(提案件数セル / 面談件数セル, "")
③提案(見積提示)→契約CVR   : =IFERROR(契約件数セル / 提案件数セル, "")
```

※`週次報告記録!$E:$E`等はANDPAD側データの列、`$K$2`/`$L$2`は`コンバージョンレート`シート自身の実効期間セル(2-1節)。既存シート（今回のケース）は`週次報告記録`側の列位置が異なるため、実際に追加された列アルファベットに置き換えること。

## 4. 数式（15カテゴリ別、新規シート想定の列: C=案件種別、$A13=カテゴリ名セル、行13〜27）

```
アプローチ数: =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$E:$E, ">="&$K$2, 週次報告記録!$E:$E, "<="&$L$2)
面談数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$F:$F, ">="&$K$2, 週次報告記録!$F:$F, "<="&$L$2)
提案数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$G:$G, ">="&$K$2, 週次報告記録!$G:$G, "<="&$L$2)
契約数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                        週次報告記録!$H:$H, ">="&$K$2, 週次報告記録!$H:$H, "<="&$L$2)

①アプローチ→面談CVR    : =IFERROR(面談数セル / アプローチ数セル, "")
②面談→提案(見積提示)CVR : =IFERROR(提案数セル / 面談数セル, "")
③提案(見積提示)→契約CVR : =IFERROR(契約数セル / 提案数セル, "")
```

行13〜27をそのまま下にコピーすれば15カテゴリ全行分が完成する（`$A13`が各行のカテゴリ名セルを自動的に指すため、数式自体は全行共通）。

属性別ブロックは `$C:$C`(案件種別列) を `$D:$D`(属性列) に、カテゴリ名セルを属性リストのセルに置き換えるだけで同一パターン。

## 5. 可視化

- ダッシュボード上の「全体」表（件数4行 + CVR%3行）を元に、**棒グラフ(件数) + 折れ線(CVR%)の組み合わせグラフ**を挿入。
- 15カテゴリ別表は**横棒グラフ**でカテゴリ間のCVR%比較を可視化（0件のカテゴリも常に表示されるため、比較しやすい）。
- 月別・週別の時系列推移を見たい場合は、B2/D2を都度手で書き換える運用ではなく7節のロング形式テーブルを使う（月・週ごとに自動算出された行をそのまま折れ線グラフの元データにできる）。

## 6. 担当者別集計テーブル（`週次報告記録` の「氏名」列基準）

案件種別・属性と同じCOUNTIFSパターンで、条件列を「氏名」に差し替えるだけで担当者別CVRを算出できる。担当者名の取得方法として、用途に応じて3案を使い分ける。以下の数式は氏名列を仮に`I列`とする（実際の列アルファベットに置き換えること。「氏名」はSTAGE_COLUMN_ALIASESの対象外でANDPAD側の値がそのまま入るため、列位置はANDPAD出力に依存する）。

### 案A: 一覧表形式（`UNIQUE`展開、全担当者のランキング表示向け）

```
31 【担当者別】
32 氏名           アプローチ  面談  提案(見積提示)  契約  ①面談CVR  ②提案CVR  ③契約CVR
33 =UNIQUE(...)    ...
34 (以下スピル)
```

- A33: `=UNIQUE(週次報告記録!$I2:$I)`。空欄や見出し行の混入を避けたい場合は
  `=SORT(UNIQUE(FILTER(週次報告記録!$I2:$I, 週次報告記録!$I2:$I<>"")))` のように空欄除外・並べ替えを追加する。
- B33〜H33に下記の数式を入れてA33からのスピル範囲ぶんだけ下にコピーすれば、担当者の増減に自動追従する。

```
アプローチ数: =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$E:$E, ">="&$K$2, 週次報告記録!$E:$E, "<="&$L$2)
面談数     : =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$F:$F, ">="&$K$2, 週次報告記録!$F:$F, "<="&$L$2)
提案数     : =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$G:$G, ">="&$K$2, 週次報告記録!$G:$G, "<="&$L$2)
契約数     : =COUNTIFS(週次報告記録!$I:$I, $A33,
                        週次報告記録!$H:$H, ">="&$K$2, 週次報告記録!$H:$H, "<="&$L$2)

①アプローチ→面談CVR    : =IFERROR(面談数セル / アプローチ数セル, "")
②面談→提案(見積提示)CVR : =IFERROR(提案数セル / 面談数セル, "")
③提案(見積提示)→契約CVR : =IFERROR(契約数セル / 提案数セル, "")
```

### 案B: ドロップダウン切替形式（個人別スコアカード、1on1向け）

```
36 担当者選択: [▼ドロップダウン]
37
38 【選択した担当者の全体CVR】
39              件数         CVR%
40 アプローチ    =件数式      -
41 面談         =件数式      =B41/B40
42 提案(見積提示) =件数式      =B42/B41
43 契約         =件数式      =B43/B42
```

- B36セルに「データの入力規則 > リストを範囲で指定」を設定し、範囲に案Aの氏名一覧(`$A$33:$A`)を指定してプルダウン化する。
- B40〜B43の数式は案Aと同じCOUNTIFSで、条件セルを`$A33`(行ごとの氏名)から`$B$36`(選択中の担当者)に差し替えるだけ:
  `=COUNTIFS(週次報告記録!$I:$I, $B$36, 週次報告記録!$E:$E, ">="&$K$2, 週次報告記録!$E:$E, "<="&$L$2)` （面談/提案/契約も同様に列だけ差し替え）。
- 全員を横並びで比較したい時は案A、特定の1人を深掘りしたい時（1on1・週次面談等）は案Bが向いている。同一シートに両方併設しても数式は競合しない。

### 案C: 主要メンバー固定行展開

- 人数が少ない、または特定の主要メンバーだけを常に追いたい場合は、案Aの`UNIQUE`の代わりにA33以降へ氏名を手入力で固定する（15カテゴリ別ブロックと同じ「固定リスト」パターン）。数式は案Aと同一。異動等で担当者が変わった際は手動更新が必要になる点のみ案Aと異なる。

## 7. 月別 / 週別 時系列集計テーブル

### 7-0. 設計方針

- 「月」「週」は`週次報告記録`に列として持たせず、既存の4ステータス日付列(E〜H)へのCOUNTIFS期間条件を月・週の範囲に変えるだけで算出する（1〜6節の期間条件($K$2/$L$2、2-1節)を月・週の自動計算値に差し替えるイメージ）。
- 「対象月×カテゴリ」「対象月×担当者」のような2軸表は、**月リスト×軸リストの総当たり(クロス結合)をINDEX/MODで自動生成するロング形式(1行=1組み合わせ)**で構成する。月ごとに15行ブロックをコピーする方式より行の増減がしやすく、後段の`FILTER`・スライサー・グラフとも相性が良い。

### 7-1. 月リスト・カテゴリリストの準備(ヘルパー範囲)

```
M1  開始月    2026/01/01   ← 手入力(以後は数式で連番生成)
M2  =EDATE($M$1,ROW()-2)   ← M2から下に必要な月数分コピー(例: M13まで12ヶ月)
...
M13 =EDATE($M$1,ROW()-2)

N1  =案件種別別ブロックの1列目を参照 (例: ='コンバージョンレート'!$A$13)
...
N15 (4節の15カテゴリと同じ並び。二重管理を避けるため参照で持たせる)
```

### 7-2. 月別 × カテゴリ別 集計テーブル(ロング形式、12ヶ月×15カテゴリ=180行の例)

```
   A(対象月)   B(カテゴリ)   C(アプローチ数) D(面談数) E(提案数) F(契約数) G(①CVR) H(②CVR) I(③CVR)
50 2026/01     事業者用PV     ...
51 2026/01     リパワリング   ...
...(15行/月)
64 2026/01     その他         ...
65 2026/02     事業者用PV     ...
...
229 2026/12    その他         ...
```

50行目の数式(以降229行目まで下にコピーするだけで完成):

```
対象月   : =INDEX($M$2:$M$13, INT((ROW()-50)/15)+1)
カテゴリ : =INDEX($N$1:$N$15, MOD(ROW()-50,15)+1)

アプローチ数: =COUNTIFS(週次報告記録!$C:$C, $B50,
                        週次報告記録!$E:$E, ">="&$A50, 週次報告記録!$E:$E, "<"&EDATE($A50,1))
面談数     : =COUNTIFS(週次報告記録!$C:$C, $B50,
                        週次報告記録!$F:$F, ">="&$A50, 週次報告記録!$F:$F, "<"&EDATE($A50,1))
提案数     : =COUNTIFS(週次報告記録!$C:$C, $B50,
                        週次報告記録!$G:$G, ">="&$A50, 週次報告記録!$G:$G, "<"&EDATE($A50,1))
契約数     : =COUNTIFS(週次報告記録!$C:$C, $B50,
                        週次報告記録!$H:$H, ">="&$A50, 週次報告記録!$H:$H, "<"&EDATE($A50,1))

①アプローチ→面談CVR    : =IFERROR(面談数セル / アプローチ数セル, "")
②面談→提案(見積提示)CVR : =IFERROR(提案数セル / 面談数セル, "")
③提案(見積提示)→契約CVR : =IFERROR(契約数セル / 提案数セル, "")
```

月数を増減したい場合は、M列の月リストの行数を増減し、コピーする行範囲もそれに合わせて調整する（15の倍数で行数が決まる）。

### 7-3. 月別 × 担当者別 集計テーブル(ロング形式)

6節案Aの担当者UNIQUEリスト(`$A$33`、スピル範囲`$A$33#`)を「担当者リスト」として、7-2と同じINDEX/MODパターンで組む。担当者数は可変なので`COUNTA`で都度人数を取得する。

```
対象月   : =INDEX($M$2:$M$13, INT((ROW()-230)/COUNTA($A$33#))+1)
担当者   : =INDEX($A$33#, MOD(ROW()-230, COUNTA($A$33#))+1)

アプローチ数: =COUNTIFS(週次報告記録!$I:$I, $B230,
                        週次報告記録!$E:$E, ">="&$A230, 週次報告記録!$E:$E, "<"&EDATE($A230,1))
```

（面談数/提案数/契約数/①②③CVRは7-2と同じパターンで、条件列を`$I:$I`(氏名)のまま、日付列だけF/G/Hに差し替える。開始行230は例で、7-2の表の直下など空いている行に置き換えること）

### 7-4. 月選択ドロップダウンフィルター(任意)

- P1セルに「対象月選択」用ドロップダウンを設置。データの入力規則でリストを「全期間」+`$M$2:$M$13`を結合した範囲(例: 別セルに`={"全期間";TEXT($M$2:$M$13,"yyyy/mm")}`のような配列を作りそれを参照)から選べるようにする。
- 7-2/7-3のロング形式テーブルは「生成用の全月データ」としてそのまま保持し、画面に見せる部分は`FILTER`で絞り込んだ別ブロックにする:

```
=FILTER(A50:I229, (P1="全期間") + (A50:A229=P1))
```

  選択した月だけの15カテゴリ(または担当者)行が表示され、「全期間」を選ぶと全月表示に戻る。
- **週単位**で絞り込みたい場合は、月リスト(M列)の代わりに「週リスト(土曜始まり)」を用意し(1行目=起点の土曜日、2行目以降`=前週+7`)、`EDATE($A50,1)`の代わりに`$A50+7`を期間の上限に使う以外は7-2/7-3と同じ数式パターンで組める。週の区切りは`週次報告記録`の対象期間区切り行と同じ「土曜〜金曜」に揃えておくと運用上わかりやすい。
- 数式を使わず簡易に済ませたい場合は、スプレッドシート標準の**スライサー**機能（データ > スライサーを追加 > 対象月/対象週列を指定）を7-2/7-3の表に設定するだけでも同等のドロップダウン絞り込みができる（この場合、上記`FILTER`式は不要）。

## 前提・注意

- 列の自動追加・表記ゆれ正規化・案件種別の自動判定は`syncWeeklyReports`実行時のみ行われる。導入後、最初の週次実行が終わってから`週次報告記録`の1行目を確認し、本ドキュメントの数式内の列アルファベットを実際の列位置に合わせて修正すること。
- 「提案日」「契約日」等の段階日付列に対応するANDPAD側の項目名が`Config.gs`の`STAGE_COLUMN_ALIASES`に登録されていない場合、正規化されず別列として追加される。ANDPAD側の実際の出力ヘッダーを確認し、必要な別名を`STAGE_COLUMN_ALIASES`に追加すること。
- ANDPAD側にそもそも段階日付の項目が存在しない場合（現在ステータスのみ管理している等）は、ANDPAD側に項目追加を依頼するか、当該シートで手動運用（ステータス更新時に日付を都度記入）する運用ルールが必要。現状のスクリプトはANDPAD由来のデータをそのまま転記するのみで、ステータス値から日付を自動生成する処理は行っていない。
- `classifyCategory_`は案件(引合)名の文字列に対する単純なキーワード部分一致であり、`CATEGORY_RULES`に登録した文言が実際の案件名に含まれていなければ「その他」に分類される。運用開始後、「その他」に分類された件数が多い場合はANDPAD側の実際の命名パターンを確認し、`CATEGORY_RULES`のkeywordsを追加すること。
- 「案件（引合）名」に対応する列がANDPAD側に無い(`PROJECT_NAME_COLUMN_CANDIDATES`のいずれにも一致しない)場合、案件種別の自動判定は行われず、その回の取り込みでは「案件種別」列は空欄のままになる。
- 「氏名」列はSTAGE_COLUMN_ALIASESの対象外で、ANDPAD側の値がそのまま転記される。表記ゆれ（全角/半角スペースの有無、姓名の区切り方の違いなど）があると、`UNIQUE`が同一人物を別の担当者として分けてしまう場合がある。気になる場合は氏名列に対して`TRIM`前処理を挟むか、`STAGE_COLUMN_ALIASES`と同様の正規化ルールをスクリプト側に追加することを検討する。
- 7節のINDEX/MODによるロング形式テーブルはGoogleスプレッドシートの数式のみで完結するが、行数(月数×カテゴリ数/担当者数)が多くなるとCOUNTIFSの再計算負荷が上がる。担当者数が多い、または月数を長期間分持ちたい場合は、素朴なCOUNTIFSの代わりにQUERY関数や(必要なら)Apps Scriptでの事前集計への切り替えも検討余地がある。
- B2(開始日)>D2(終了日)のような逆転した日付を入力してしまうと、実効期間(K2〜L2)が空区間になりCOUNTIFSは常に0を返す（エラーにはならない）。入力ミス防止のため、B2・D2に「日付」のデータ入力規則を設定し、必要であれば条件付き書式で`B2<>"" と D2<>"" と B2>D2`のときにセルを警告色にする運用を検討する。
- 7節の月別/週別テーブルは、この2節の期間セル(B2/D2, 実効期間K2/L2)とは**独立した仕組み**（月・週の境界は7-1節のM列/週リストから計算する）。B2/D2を変更しても7節のロング形式テーブルの値は変わらない点に注意（7節側だけを絞り込みたい場合は7-4節の月選択ドロップダウンを使う）。
