# CVR(コンバージョンレート)KPI 集計・可視化 設計案

対象: 「31期予材リスト」スプレッドシート > `週次報告記録` シート

## 結論

- `週次報告記録`(生データ)に **段階到達日** 4列（アプローチ日/面談日/見積日/契約日）を追加する。
  - 現状の「ステータス」1列（現在の最新状態のみ保持）方式だと、契約まで進んだ案件は「見積」のカウントから漏れてCVRが不正確になるため。
  - 既存シートに近い列（例: ステータス変更日など）が既にあればそれを流用してもよい。
- 生データはそのまま集計に使わず、新規シート `CVRダッシュボード` を追加し、そこに COUNTIFS ベースの集計表を作る（生データを直接いじらない = ANDPAD自動追記との衝突を避ける）。
- 全体集計とカテゴリ別（案件種別・属性）集計を同一シート内に並べ、期間セル(開始/終了日)を変えるだけで両方が再計算される構成にする。
- **実装済み**: `Config.gs`(`STAGE_COLUMN_ALIASES`) + `WeeklySync.gs`(`resolveCanonicalHeader_` / `ensureColumnsExist_` / `getTargetSheet_`) を修正し、ANDPAD側の表記ゆれ（例:「初回接触日」→「アプローチ日」）を正規化のうえ、この6列（案件種別/属性/アプローチ日/面談日/見積日/契約日）を`syncWeeklyReports`実行時に必ず存在させるようにした。`コード.gs`（単一ファイル版）にも同内容を反映済み。

---

## 1. `週次報告記録` 側の追加列（案）

既存列（取込日時, 元ファイル名, ...案件情報...）はそのまま。末尾に以下を追加:

| 列名 | 内容 |
| --- | --- |
| 案件種別 | 例: 新築 / リフォーム / 外構 など（カテゴリ①） |
| 属性 | 例: 紹介 / 反響 / 法人 など（カテゴリ②） |
| アプローチ日 | 初回接触した日。未到達なら空欄 |
| 面談日 | 面談実施日。未到達なら空欄 |
| 見積日 | 見積提出日。未到達なら空欄 |
| 契約日 | 契約日。未到達なら空欄 |

**列位置**:
- 未使用の新規シート（`getTargetSheet_`が初回作成する場合）は必ず A=取込日時, B=元ファイル名, C=案件種別, D=属性, E=アプローチ日, F=面談日, G=見積日, H=契約日 の順で作られる。
- 既に運用中の`週次報告記録`（今回のケース）は、次回`syncWeeklyReports`実行時に不足している6列が**既存ヘッダーの末尾**に自動追加される（既存列の並びは変更しない）。実行後にシートの1行目を確認し、実際に追加された列アルファベットを本ドキュメントのC〜Hの代わりに読み替えること。
- ANDPAD側の項目名が`STAGE_COLUMN_ALIASES`(`Config.gs`)の別名リストに一致しない場合は正規化されず、元の項目名のまま別列として追加されるので、実際の出力を確認して別名リストに追記する運用とする。

## 2. `CVRダッシュボード` シート レイアウト案

```
   A            B            C
1  期間開始      2026/07/01
2  期間終了      2026/07/31
3
4  【全体】
5              件数         CVR%
6  アプローチ    =件数式      -
7  面談         =件数式      =G7/G6
8  見積         =件数式      =G8/G7
9  契約         =件数式      =G9/G8
11 【案件種別別】
12 案件種別  アプローチ  面談  見積  契約  面談CVR  見積CVR  契約CVR
13 新築       ...
14 リフォーム ...
...
20 【属性別】（同じ列構成をもう1ブロック）
```

- B1/B2: 日付セル（データの入力規則で日付ピッカー化）
- カテゴリ別ブロックの1列目は `=UNIQUE(週次報告記録!C2:C)` で自動リスト化（案件種別・属性それぞれ、実際の列アルファベットに置き換え）
- CVR%セルは表示形式を「パーセント」に設定

---

## 3. 数式（全体集計、B1/B2=期間開始・終了、新規シート想定の列: E=アプローチ日,F=面談日,G=見積日,H=契約日）

```
アプローチ件数: =COUNTIFS(週次報告記録!$E:$E, ">="&$B$1, 週次報告記録!$E:$E, "<="&$B$2)
面談件数     : =COUNTIFS(週次報告記録!$F:$F, ">="&$B$1, 週次報告記録!$F:$F, "<="&$B$2)
見積件数     : =COUNTIFS(週次報告記録!$G:$G, ">="&$B$1, 週次報告記録!$G:$G, "<="&$B$2)
契約件数     : =COUNTIFS(週次報告記録!$H:$H, ">="&$B$1, 週次報告記録!$H:$H, "<="&$B$2)

①見積→契約CVR      : =IFERROR(契約件数セル / 見積件数セル, "")
②面談→見積CVR      : =IFERROR(見積件数セル / 面談件数セル, "")
③アプローチ→面談CVR : =IFERROR(面談件数セル / アプローチ件数セル, "")
```

※既存シート（今回のケース）は列位置が異なるため、実際に追加された列アルファベットに置き換えること。

## 4. 数式（カテゴリ別、新規シート想定の列: C=案件種別、$A13=カテゴリ名セル）

```
アプローチ件数: =COUNTIFS(週次報告記録!$C:$C, $A13,
                          週次報告記録!$E:$E, ">="&$B$1, 週次報告記録!$E:$E, "<="&$B$2)
面談件数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                          週次報告記録!$F:$F, ">="&$B$1, 週次報告記録!$F:$F, "<="&$B$2)
見積件数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                          週次報告記録!$G:$G, ">="&$B$1, 週次報告記録!$G:$G, "<="&$B$2)
契約件数     : =COUNTIFS(週次報告記録!$C:$C, $A13,
                          週次報告記録!$H:$H, ">="&$B$1, 週次報告記録!$H:$H, "<="&$B$2)

各CVR% = 上と同じ割り算（IFERRORでラップ）
```

属性別ブロックは `$C:$C`(案件種別列) を `$D:$D`(属性列) に、`$A13` を属性リストのセルに置き換えるだけで同一パターン。

---

## 5. 可視化

- ダッシュボード上の「全体」表（件数4行 + CVR%3行）を元に、**棒グラフ(件数) + 折れ線(CVR%)の組み合わせグラフ**を挿入。
- カテゴリ別表は**横棒グラフ**でカテゴリ間のCVR%比較を可視化。
- 週推移を見たい場合は、B1/B2に週の開始/終了を入れて同じ数式を1週間ごとにコピーした「週次推移表」を別ブロックに用意し、折れ線グラフで時系列表示（QUERYで自動生成も可だが、まずはCOUNTIFSの手動コピーで十分運用可能）。

---

## 前提・注意

- 列の自動追加・表記ゆれ正規化は`syncWeeklyReports`実行時のみ行われる。導入後、最初の週次実行が終わってから`週次報告記録`の1行目を確認し、本ドキュメントの数式内の列アルファベットを実際の列位置に合わせて修正すること。
- 「見積日」「契約日」等の段階日付列に対応するANDPAD側の項目名が`Config.gs`の`STAGE_COLUMN_ALIASES`に登録されていない場合、正規化されず別列として追加される。ANDPAD側の実際の出力ヘッダーを確認し、必要な別名を`STAGE_COLUMN_ALIASES`に追加すること。
- ANDPAD側にそもそも段階日付の項目が存在しない場合（現在ステータスのみ管理している等）は、ANDPAD側に項目追加を依頼するか、当該シートで手動運用（ステータス更新時に日付を都度記入）する運用ルールが必要。現状のスクリプトはANDPAD由来のデータをそのまま転記するのみで、ステータス値から日付を自動生成する処理は行っていない。
